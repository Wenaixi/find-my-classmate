# 领域文档

本文件规定各工程技能在探索代码库时，如何消费本仓库的领域文档。

## 探索前先读这些

- 仓库根目录的 **`CONTEXT.md`**；或
- 若根目录存在 **`CONTEXT-MAP.md`**：它指向每个上下文各自的 `CONTEXT.md`，按主题读取相关的那几份；
- **`docs/adr/`**：读取与即将改动的区域相关的 ADR。

若上述文件不存在，**静默继续**。不要因为缺失而提示，也不要预先建议创建它们。`/domain-modeling` 技能（由 `/grill-with-docs` 与 `/improve-codebase-architecture` 调用）会在术语或决策真正敲定时按需惰性创建。

## 文件结构

本仓库为单上下文布局：

```
/
├── CONTEXT.md
├── docs/adr/
│   ├── 0001-student-type-not-split.md
│   └── 0002-<slug>.md
└── src/
```

新增 ADR 沿用既有四位数字编号，从当前最大编号递增。

## 使用术语表中的措辞

当输出中提到某个领域概念（issue 标题、重构提案、假设、测试名称）时，使用 `CONTEXT.md` 中定义的术语。不要漂移到术语表明确排除的同义词。

若所需概念尚未收录，先自问：这是项目独有的概念，还是通用编程概念？只有前者才配进入术语表。若确有缺口，记下来交给 `/domain-modeling` 处理。

## 标出与 ADR 的冲突

若输出与既有 ADR 相抵触，必须显式点出，而不是静默覆盖：

> _与 ADR-0007（事件溯源订单）冲突，但值得重开，因为……_
